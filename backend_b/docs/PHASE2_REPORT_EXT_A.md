# Phase 2 Extension A: Backup DNS Server & Failover
**Author:** Anwesha Adhikari (Mac 4 Lead)

To eliminate the primary DNS server (Mac 1) as a single point of failure in our local private network architecture, a secondary `dnsmasq` instance was configured and hosted on Mac 4 (`10.7.19.42`). The backup server was configured with `interface=en0` and `local-ttl=30`, serving authoritative records for `app.cnteam.test` and `api.cnteam.test` identical to the primary server (`10.7.3.251`). Client macOS resolvers were populated with both name servers (`10.7.22.176` primary, `10.7.19.42` secondary). When the primary DNS service on Mac 1 was intentionally stopped to simulate an outage, client queries were transparently handled by Mac 4's `dnsmasq` instance without manual client intervention or connection timeouts. Live packet inspection and `dnsmasq` query logs verified query migration, demonstrating independent failure domains and resolver failover resilience analogous to multi-nameserver cloud DNS zones (e.g., AWS Route 53).
